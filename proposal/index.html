12개 기능군을 세 개의 구조로 묶었습니다

공고의 ①~⑫ 12개 기능군은 요구 목록으로 보면 흩어져 있지만, 설계로 보면 세 개의 구조로 묶입니다. 그리고 그 출발점은 소스코드 없이 규칙을 복원하는 절차입니다.

설계 관점 세 가지

설계 ① · 어디서 뽑아도 같은 숫자
집계는 한 곳에서만 계산합니다

집계 기준서의 계산식을 단일 집계 서비스 한 곳에만 구현하고, 화면·엑셀·보고서·지도는 결과를 받아 형식만 바꿉니다. 확정·마감된 기간은 발행 버전별 스냅샷으로 저장하고, 마감 후 정정은 사유·승인 시각을 기록한 새 버전으로 발행합니다.

설계 ② · 담당자는 예외 건만 확인
입력·제출·확정 단계마다 검증합니다

입력 시점에 필수값·코드 유효성과 급변을 표시하고, 제출 시점에 상세 합계 ↔ 총괄값과 재고 수지(기초 재고 + 생산 − 출하 = 기말 재고)를 교차 검증해 실패하면 제출을 막습니다. 확정 시점에는 경고·설명이 필요한 건만 협회가 확인합니다.

설계 ③ · 소수 회원사 지역의 역산 차단
회원사 간 격리는 화면이 아니라 서버에서 판정합니다

조회 대상 회원사를 로그인 세션에서 서버가 강제로 적용하고, 합계 조회에 최소 구성 회사 수 임계값을 적용합니다. 상위 합계에서 하위 합계를 빼거나 기간·품목별 결과를 비교해 개별 수치가 드러나면 관련 합계도 함께 비공개 처리합니다.

  • 상태 머신 — 작성 중 → 제출 → (보완 요청 → 작성 중) → 확정 → 마감. 단계 건너뛰기를 서버에서 차단하고, 전이마다 수행자·시각을 기록합니다.
  • 세 단계 검증 — 입력 시점 필수값·코드 유효성·급변 경고, 제출 시점 상세 합계 ↔ 총괄값과 재고 수지(기초 재고 + 생산 − 출하 = 기말 재고) 교차 검증. 필수 검증을 통과하지 못한 자료는 제출을 막고 회원사가 수정합니다.
  • 회원사별 제출 현황판 — 10개사의 제출·보완·확정 상태를 한 화면에서 보고, 목록에서 바로 알림을 발송합니다. 알림은 제출 완료 · 보완 요청 · 마감 임박(제출 요청) 3종입니다.
  • 마감 후 정정은 원본을 덮어쓰지 않습니다 — 승인되면 기존 발행 버전은 보존한 채 새 집계 스냅샷 버전을 만들고, 조회 화면에 발행 버전과 정정 반영 시점을 표시합니다.
  • 단일 집계 서비스 — 화면·엑셀·보고서·지도 네 경로는 이 서비스의 결과를 받아 형식만 바꿉니다. 새 보고서 양식을 추가해도 계산식은 늘지 않으며, 경로 간 일치 시험으로 검증합니다.
  • 발행 버전별 스냅샷 — 기준정보(회원사 합병·공장 폐쇄·코드 개정)가 바뀌어도 기존 발행 버전은 변하지 않고, 정정 승인 시 사유·승인 시각을 단 새 버전을 발행합니다.
  • 양식 재현 — 대표 엑셀·보고서 양식 1종은 병합 셀·다단 제목·글꼴·괘선까지 재현하고, 나머지 양식군 3개는 표 구조와 계산식을 재현합니다. 양식 추가는 별도 견적 B의 단가로 산정합니다.
  • 조회·다운로드·차트 — 기간·회원사·공장·품목·지역별 조회와 항목 선택 다운로드, 조회 조건 저장(계정당 10건), 추이 차트 표준 4종(월별 추이, 전년 동기 비교, 회원사·품목 비중, 누계)을 제공합니다.
  • 공장 위치 지도 — 공장 주소를 좌표로 변환해 표시하고, 표시를 누르면 공장 정보 창이 열립니다.
  • 지역별 출하량 단계 구분도 — 시·도 경계를 출하량에 따라 색 단계로 칠하고 기간·품목을 선택합니다. 시·군·구 확대를 기본 요구로 유지하며, 대안 화면은 협회의 범위·인수 기준 변경 승인이 있어야 적용합니다.
